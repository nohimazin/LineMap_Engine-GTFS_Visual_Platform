## 3. GTFS静的データの処理フロー

```text
GTFS ZIP
  │
  ├─ routes.txt       路線属性・色
  ├─ trips.txt        trip_id・route_id・shape_id
  ├─ shapes.txt       路線形状（任意）
  ├─ stops.txt        停留所位置・名称
  └─ stop_times.txt   tripごとの停留所順序（任意）
  │
  ▼
parse_gtfs_zip()
  │
  ├─ routes_geojson
  ├─ stops_geojson
  ├─ stop_connections_geojson
  ├─ trip_to_route
  └─ route_catalog
  │
  ▼
DataStore.update_gtfs()
  │
  ▼
GET /routes
GET /stops
GET /stop_connections
GET /route_catalog
  │
  ▼
MapLibre GeoJSON source / layer
```

`shapes.txt`が存在する場合、停留所をshape上へ投影して連結線を生成します。shapeがない場合は、停留所座標を順番に結んだLineStringを生成します。

## 4. GTFS-RT処理フロー

```text
POST /settings/gtfs_rt
  │
  ▼
RealtimeVehicleService.configure()
  │
  ▼
lifespanで起動したpolling_loop()
  │
  ▼
GTFS-RT Vehicle Positions protobuf
  │
  ├─ vehicle position
  ├─ vehicle_id
  ├─ trip_id
  ├─ route_id
  ├─ bearing / speed
  └─ timestamp
  │
  ▼
GET /vehicles
  │
  ▼
vehicles-symbolレイヤー
```

RTのroute_idが空の場合は、静的GTFSから作成した`trip_to_route`で補完します。

## 6. フロントエンドレイヤー

```text
routes
  ├─ routes-line       可視路線
  └─ routes-line-hit   路線クリック用透明線

stop-connections
  ├─ stop-connections-line      停留所連結線
  └─ stop-connections-line-hit  連結線クリック用透明線

stops
  └─ stops-circle      停留所

vehicles
  └─ vehicles-symbol   bearing対応車両矢印
```

路線と停留所連結線は`route_id`によるフィルターで表示対象を制御します。統合表示時はブラウザ側でルートカタログとGeoJSONを再構成します。

## 7. データ保存と再起動時の制約

現行SQLiteスキーマは次の単一キー構成です。

```sql
CREATE TABLE blobs (
    key TEXT PRIMARY KEY,
    payload TEXT NOT NULL
);
```

そのため、複数GTFSは実行中のメモリには保持できますが、`gtfs_id`単位でSQLiteへ永続化されません。再起動後の複数GTFS一覧・選択状態・全GTFSデータの復元は未対応です。

将来の永続化では、少なくとも以下を管理する必要があります。

- `gtfs_id`
- GTFS表示名
- 登録日時
- 現在選択中かどうか
- 各GTFSのGeoJSON・route catalog・trip mapping

## 9. 現在の制約

- 往復統合の中心線は2つの形状を平均化する近似線です
- route_long_nameの表記揺れによって統合判定が変わります
- 大規模GTFSでは、解析時のメモリ使用量とブラウザ描画負荷に注意が必要です
- GTFS-RTはVehicle Positions protobufを対象としています
- RTのroute_idと静的GTFSのroute_idが一致しない場合、路線紐付けが不完全になります
- `tests/test_route_merge.py`が参照する`data/route_merge_testcases.json`は現行ツリーで未確認です

## 10. 起動

```text
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

ブラウザで`http://127.0.0.1:8000`を開きます。
